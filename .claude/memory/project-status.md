## 반응 속도 (2026-09-07 저녁)

실제 녹화 검증은 끝났습니다. 데스크톱 캡처와 게임 녹화(귀무자) 모두 저장 폴더가
제대로 표시되었습니다. 다만 시작(Alt+F9)과 중단을 누른 뒤 화면이 바뀌기까지
4~5초가 걸려서, 사용자가 1초 안에 반영되기를 요구했습니다.

그래서 `scan.being_written()` 과 `fast_detect` 설정을 넣고 폴링 주기 기본값을
0.5초로 낮췄습니다. 자세한 내용은 [[shadowplay-writes-mp4-directly]] 에 적어
두었습니다. 가짜 파일로 하는 검사 10종은 모두 통과했지만, **실제 ShadowPlay
녹화로는 아직 확인하지 못했습니다.** 확인할 것은 세 가지입니다.

- 시작과 중단이 1초 안에 화면에 반영되는지
- 녹화 도중에 "파일 닫힘" 으로 잘못 중단 판정하지 않는지 (긴 녹화로 확인)
- 즉시 재생 버퍼처럼 항상 열려 있는 파일 때문에 대기 중에 녹화로 오판하지 않는지

어긋나면 `test\trace_growth.py` 로 실제 파일의 크기 갱신과 잠금 상태를 0.1초
단위로 기록해서 원인을 봅니다. Alt+F9 를 누른 순간 스페이스를 눌러 표시를
남기면, 사람이 누른 시각과 파일에 반영된 시각을 견줄 수 있습니다. 이 도구는
설정값을 달리했을 때의 판정 시각도 함께 계산해 줍니다.

만약 NVIDIA App 이 hotkey 를 누른 뒤 몇 초 지나서야 파일을 만드는 것이라면,
폴더를 감시하는 방식으로는 그보다 빨리 알 수 없습니다. 그때는 이 도구의 표시
시각과 파일 생성 시각의 차이가 그대로 하한이 됩니다.

## 중복 실행 방지 (2026-09-07)

사용자 PC 에서 EXE 가 두 개 동시에 떠 있는 것을 발견해서 `component/instance.py` 를
넣었습니다. 이름 붙인 뮤텍스를 잡고, 이미 잡혀 있으면 `FindWindowW` 로 원래 창을
앞으로 끌어온 뒤 물러납니다. 타이틀바가 없는 창(`overrideredirect`)이어도 창 제목은
남아 있어서 `FindWindowW` 가 찾아냅니다. EXE 로도 확인했습니다.

- **버전은 커밋할 때까지 1.0.0 을 유지합니다.** 아직 배포한 적이 없으므로
  개발 도중에 무엇을 고쳐도 번호를 올리지 않습니다.

- **CHANGELOG 는 앱을 쓰는 사람이 읽는 문서입니다.** 빌드 방법, 모듈 분리,
  검증 도구처럼 사용자가 마주치지 않는 것은 기능이 아니므로 적지 않습니다.
- 2026-09-07 에 프로젝트 폴더 이름에서 공백을 뺐습니다(`F:\ShadowPlay Notifier`
  -> `F:\ShadowPlayNotifier`). 제품 이름 `ShadowPlay Notifier` 는 공백을 그대로
  둡니다. 둘은 다른 값이므로 함께 바꾸지 마십시오.
- **빌드하거나 검증 도구를 돌리기 전에 앱이 실행 중인지 반드시 확인하고 닫습니다.**

## 사용자 환경에서 걸린 문제

2026-09-07 저녁에 **ShadowPlay 의 Alt+F9 녹화가 동작하지 않는다**는 보고가 있었고,
재부팅 후 다시 시험해 보기로 했습니다. 이 앱은 폴더를 읽기만 하므로 원인이 될 수
없습니다. 짚어 볼 곳은 NVIDIA App 쪽입니다.

- 녹화 상태 표시 아이콘이 영상에 찍히는 것이 싫어서 그 표시를 껐다는 것이 이 프로그램을
  만든 계기입니다([[shadowplay-writes-mp4-directly]] 와 README 의 "만든 이유" 참고).
  이때 상태 표시기만 끈 것이 아니라 **인게임 오버레이 자체를 껐다면 Alt+F9 단축키도
  함께 죽습니다.** 단축키는 오버레이가 잡고 있기 때문입니다.
- 그 밖에 확인할 것: 즉시 재생/수동 녹화 기능이 켜져 있는지, 다른 프로그램이 같은
  단축키를 쓰고 있는지, NVIDIA App 업데이트 후 설정이 초기화되었는지.
