2026년 9월 7일에 `E:\shadowplay record` 를 살펴본 결과입니다.

- 하위 폴더는 게임 이름으로 나뉩니다(`OnimushaWotS`, `Dawnwalker`, `FFRS`, `Desktop` 등).
- 파일은 `.mp4` 20개, 그 밖에 `.json` 과 `.pb` 뿐이며 **`.tmp` 는 하나도 없습니다.**
- 녹화 파일 이름은 `<폴더 이름> 2026.09.06 - 12.15.01.04.mp4` 형식이고, 큰 것은 57GB 에 이릅니다.

즉 NVIDIA App 이 `.mp4` 파일 자체를 키우면서 기록합니다. 그래서 `_stop()` 의 세 경로 중
"임시 파일 사라짐" 과 "완료 파일 생성" 은 실제로 쓰이지 않고, **크기 증가가 멈춘 뒤
stall 시간이 지나는 경로만 동작합니다.** 기본값 8초가 곧 중단 표시까지의 지연입니다.

같은 날 12시 8분에 실제 녹화(`Desktop\Desktop 2026.09.07 - 12.08.01.07.mp4`)를
시작 감지까지 확인했습니다.

## 그래서 잠금 신호를 얹었습니다 (v1.1.0, 2026-09-07)

같은 날 실제 녹화로 시험한 결과 시작과 중단 모두 4~5초 늦게 표시되었고, 사용자가
1초 안에 반영되기를 요구했습니다. stall 값을 줄이는 것으로는 도달할 수 없어서
`scan.being_written()` 을 더했습니다. 파일을 읽기 권한으로만, 공유는 읽기까지만
허용해서 열어 보고 공유 위반이 나면 다른 프로세스가 쓰고 있다는 뜻입니다.
녹화 중에는 mp4 가 계속 열려 있고 중단하는 순간 닫히므로, 이것이 곧 중단 신호입니다.

**Why:** stall 값을 줄이면 중단 표시가 빨라지지만, 녹화 중 일시적으로 파일 크기가
갱신되지 않는 순간에 잘못 중단으로 판정할 위험이 함께 커집니다. 잠금 신호는 크기와
무관한 별개의 근거라서 이 트레이드오프에 걸리지 않습니다.

**How to apply:** 중단 반응이 느리면 `stall` 을 건드리지 말고 `fast_detect` 가
켜져 있는지 먼저 확인하십시오. 잠금 확인은 크기가 늘지 않은 주기에만 하므로 녹화
중에는 거의 호출되지 않습니다. `.tmp` 를 쓰는 환경을 가정한 코드 경로도 지우지
마십시오. 다른 PC 나 드라이버 설정에서는 임시 파일을 쓸 수도 있습니다. 감시 대상
좌표와 표시 설정은 [[secondary-display]] 를 참고하십시오.
