# ShadowPlay Notifier

NVIDIA ShadowPlay(NVIDIA App)의 녹화 상태를 감시해서, 보조 디스플레이에 상시
띄워 놓고 멀리서 흘끗 보아도 녹화 여부를 판단할 수 있게 만든 tkinter GUI 앱입니다.

![녹화 중인 화면](main.png)

녹화 폴더를 일정 주기로 훑어보면서 파일 크기가 커지면 녹화 시작으로 판정하고,
크기 증가가 멈춘 채 지정한 시간(stall)이 지나면 녹화 중단으로 판정합니다.
런타임 의존성은 파이썬 표준 라이브러리와 tkinter 뿐이며, 외부 패키지를 쓰지 않습니다.
(PyInstaller 는 빌드할 때만 필요합니다.)

녹화 결과물을 읽기만 하며, 파일을 지우거나 옮기는 기능은 넣지 않았습니다.

## 만든 이유

ShadowPlay 는 녹화 중임을 알리기 위해 화면 구석에 상태 표시 아이콘을 띄웁니다.
그런데 그 아이콘이 녹화된 영상 파일에도 그대로 함께 찍힙니다. 주인장은 그것이 보기
싫어서 상태 표시 아이콘을 꺼 버렸는데, 그러고 나니 지금 녹화가 도는 중인지 아닌지
확인할 방법이 사라졌습니다.

마침 책상에 Hagibis 미니 모니터 2세대 USB 허브 도킹 스테이션을 쓰고 있었습니다.
그래서 그 보조 화면에 녹화 상태를 상시 띄워 놓고 흘끗 보아 판단하려고 이 프로그램을
만들었습니다. 화면 크기가 960x640 으로 고정되어 있고 글자를 크게 키운 것도, 손바닥만
한 그 패널을 멀리서 보아야 하기 때문입니다.

## 화면 구성

| 영역 | 내용 |
| --- | --- |
| 상태 배너 (140px) | 녹화 중에는 빨간 배경과 원형 인디케이터가 1초 주기로 밝기 펄스를 그리고 "녹화중"을 48pt 로 표시합니다. 대기 중에는 회색 배경에 펄스가 없습니다. 오른쪽에는 경과 시간을 크게 띄웁니다. |
| 상세 정보 | 저장 폴더(42pt 굵게), 파일명, 경과 시간과 용량(38pt), 비트레이트와 마지막 증가 시점(28pt)을 2열로 보여 줍니다. 마지막 증가가 3초를 넘으면 주황색, stall 임계의 75% 를 넘으면 빨간색으로 바뀝니다. 대기 중에는 직전 녹화 요약과 세션 누적 횟수를 표시합니다. |
| 이벤트 로그 | 최근 5건을 고정폭 글꼴로 남깁니다. 시작은 빨강, 중단은 하늘색, 오류는 노랑입니다. |
| 상태 표시줄 | 감시 폴더, 폴링 주기, 마지막 갱신 시각을 표시하고, 폴더에 접근할 수 없으면 경고를 덧붙입니다. 오른쪽 끝에 버전이 작게 붙습니다. |

타이틀바를 쓰지 않는 것을 기본으로 삼았습니다. 그래서 배너 오른쪽 위에 환경설정,
전체화면, 닫기 세 버튼을 배너 색에 맞추어 그려 넣었고, 창은 어느 지점을 잡아도 끌어서
옮길 수 있습니다. 버튼은 마우스를 올리면 밝아집니다. 아이콘은
[Fluent UI System Icons](https://github.com/microsoft/fluentui-system-icons)를
PNG 로 구워 소스에 넣었으므로, 실행할 때 따로 필요한 파일이 없습니다.

작은 보조 화면에서 멀리 떨어져 보는 용도이므로, 자리는 녹화 정보 쪽에 몰아주었습니다.
저장 폴더 이름이 길어서 한 줄에 들어가지 않으면 잘라내지 않고 글자 크기를 42pt 에서
24pt 까지 단계적으로 줄여서 끝까지 보여 줍니다.

## 감지 방식

한 주기 전보다 파일이 `min_growth`(기본 256KB) 이상 커지면 그 파일을 녹화 중인
파일로 잡습니다. 이후 크기 증가가 `stall` 초 동안 없으면 녹화가 끝난 것으로 봅니다.
임시 파일이 사라지거나 `outdir` 에 완성본이 생기는 경우에도 즉시 중단으로 판정합니다.

NVIDIA App 은 환경에 따라 `.tmp` 를 거치지 않고 `.mp4` 파일을 직접 키우면서 기록합니다.
이때는 중단 판정이 stall 경로로만 이루어지므로, 녹화를 멈춘 뒤 대기중으로 돌아오기까지
`stall` 초(기본 8초)가 걸립니다. 값을 낮추면 빨라지지만, 녹화 중에 파일 크기가 잠깐
갱신되지 않는 순간을 중단으로 오판할 위험이 함께 커집니다.

### 잠금 신호로 빠르게 판정하기

그래서 `fast_detect`(기본 켜짐)를 두었습니다. 녹화하는 프로그램은 기록하는 동안
파일을 쓰기 위해 열어 두고, 녹화를 멈추는 순간 그 파일을 닫습니다. 파일이 열려
있는지는 크기와 무관하게 곧바로 알 수 있으므로, 이 신호를 쓰면 `stall` 초를 기다리지
않고 폴링 주기 한 번 안에 중단을 잡아냅니다. 시작 쪽도 마찬가지로, 새로 나타난 파일이
쓰기로 열려 있으면 크기가 한 번 더 늘기를 기다리지 않고 바로 녹화 시작으로 봅니다.

확인하는 방법은 파일을 읽기 권한으로만, 그리고 공유는 읽기까지만 허용해서 여는 것입니다.
이미 다른 프로세스가 쓰고 있으면 공유 위반이 나고, 아무도 쓰고 있지 않으면 그냥 열립니다.
파일을 고치지도, 잠그지도 않습니다. 크기가 늘지 않은 주기에만 확인하므로 녹화 중에는
거의 호출되지 않고, 판단이 서지 않으면(윈도우가 아니거나 권한이 없으면) 아래에서 설명한
기존 판정으로 되돌아갑니다. 즉 이 신호는 검증된 판정 구조를 대체하지 않고 위에 얹혀
있습니다. 동작이 미덥지 않으면 `fast_detect` 를 `false` 로 두면 예전 방식만 씁니다.

폴링은 별도 스레드에서 수행하고 `queue.Queue` 로 결과를 넘기며, UI 스레드는
`after()` 루프로 100ms 마다 큐를 비웁니다. 그래서 폴더를 훑는 동안에도 창이 멈추지
않습니다. 창을 닫으면 종료 플래그가 서고 감시 스레드도 함께 끝납니다.

## 구성

역할별로 나누어 두었습니다.

```
ShadowPlayNotifier.py    진입점. 설정을 읽어 창과 감시 스레드를 이어 붙입니다.
ShadowPlayNotifier.spec  PyInstaller 빌드 정의
component/
  paths.py               설정과 로그 파일의 위치, 로그 기록, 전역 예외 처리
  config.py              config.json 읽기와 쓰기, 명령줄 인자, 최종 설정 조립
  scan.py                폴더 훑기와 표시용 단위 변환
  watcher.py             시작·중단 판정 상태 기계와 감시 스레드
  display.py             DPI 인식, 모니터 좌표, 창을 놓을 자리 결정
  theme.py               창 크기와 색, 글꼴 고르기
  text.py                화면에 넣기 좋게 문자열 다듬기
  icons.py               배너 아이콘 (SVG 를 PNG 로 구워 base64 로 넣은 것)
  app.py                 본 창의 화면 구성과 갱신
  settings_dialog.py     환경설정 창
  version.py             버전 번호
test/                    검증 도구. test/README.md 를 보십시오.
```

## 빌드

```
pyinstaller --clean ShadowPlayNotifier.spec
```

`dist\ShadowPlayNotifier.exe` 하나만 나옵니다. 빌드 설정은
[ShadowPlayNotifier.spec](ShadowPlayNotifier.spec) 에 모여 있습니다. 버전과 작성자는
`component/version.py` 에서 읽어 윈도우 파일 속성 창에 넣습니다.

`--clean` 을 반드시 붙이십시오. 그것이 없으면 PyInstaller 가 이전에 만든 EXE 를 그대로
재사용해서 바뀐 아이콘이 조용히 무시됩니다.

`app.ico` 파일을 프로젝트 폴더에 두면 EXE 아이콘으로 넣고, 없으면 아이콘 없이
빌드합니다. 아이콘 원본은 저장소에 올리지 않습니다.

PyInstaller 가 없으면 아래 명령으로 먼저 설치하십시오.

```
python -m pip install pyinstaller
```

콘솔 창 없이 도는 프로그램이므로 화면 출력이 없습니다. 실행 중에 생긴 일과 예외는
EXE 옆의 `monitor.log` 에 계속 덧붙여 기록됩니다.

## 설정

배너 오른쪽 위의 톱니바퀴를 누르면 환경설정 창이 열립니다. 녹화 폴더를 직접 고르고
폴링 주기와 판정 값, 표시할 모니터, 창 동작을 바꿀 수 있습니다. 저장하면 `config.json`
에 적고 감시를 새 설정으로 다시 시작하므로 앱을 껐다 켤 필요가 없습니다.

파일을 직접 고쳐도 됩니다. EXE(또는 스크립트)와 같은 폴더의 `config.json` 을 읽고,
없으면 기본값으로 새로 만듭니다. onefile 로 묶으면 `__file__` 이 임시 폴더를 가리키므로,
설정 경로는 `sys.executable` 기준으로 구합니다.

```json
{
  "dir": "E:\\shadowplay record",
  "outdir": "",
  "interval": 0.5,
  "stall": 8.0,
  "min_size": 1048576,
  "min_growth": 262144,
  "fast_detect": true,
  "beep": false,
  "topmost": false,
  "borderless": true,
  "monitor": -1
}
```

| 항목 | 뜻 |
| --- | --- |
| `dir` | 감시할 녹화 폴더입니다. 하위 폴더까지 훑습니다. |
| `outdir` | 완성본이 따로 떨어지는 폴더입니다. 여기에 새 파일이 생기면 즉시 중단으로 판정합니다. 쓰지 않으면 비워 둡니다. |
| `interval` | 폴링 주기(초)입니다. 값이 작을수록 반응이 빠르고 디스크를 자주 읽습니다. |
| `stall` | 파일 크기 증가가 이만큼(초) 멈추면 녹화가 끝난 것으로 판정합니다. |
| `min_size` | 이보다 작은 파일은 후보에서 제외합니다(바이트). |
| `min_growth` | 한 주기에 이만큼 커져야 녹화 시작으로 봅니다(바이트). |
| `fast_detect` | 파일이 쓰기로 열려 있는지를 함께 보고 시작과 중단을 곧바로 잡습니다. 끄면 크기 증가와 `stall` 만으로 판정하므로 중단 표시가 `stall` 초만큼 늦습니다. |
| `beep` | 시작과 중단에 짧은 소리를 냅니다. 녹화에 소리가 섞이지 않도록 기본은 꺼짐입니다. |
| `topmost` | 창을 항상 위에 둡니다. |
| `borderless` | 타이틀바를 없앱니다(기본값). 창은 어디를 잡아도 끌립니다. |
| `monitor` | 창을 띄울 모니터 번호입니다. 왼쪽 위 좌표 순서로 0부터 세며, `-1`은 자동입니다. |

`patterns`(감시할 확장자 목록)와 `recursive`(하위 폴더 포함 여부)는 기본 파일에 넣지
않지만, 직접 적어 두면 그대로 읽습니다.

### 창이 어느 화면에 뜨는가

`monitor` 를 `-1`(기본값)로 두면 다음 순서로 정합니다.

1. 해상도가 창과 똑같이 **960x640 인 모니터**가 있으면 그 화면을 씁니다.
   보조 디스플레이를 화면 가득 채우는 용도이기 때문입니다.
2. 그런 모니터가 없으면 **주 모니터 한가운데**에 띄웁니다. 보조 디스플레이가 없거나
   해상도가 더 큰 환경이 여기에 해당합니다.

번호를 직접 적으면 그 모니터를 씁니다. 다만 지정한 번호의 모니터가 없거나 창보다
작으면 경고를 로그에 남기고 위의 자동 선택으로 물러섭니다. 어떤 경우에도 창이 화면
밖으로 나가지 않습니다.

보조 디스플레이가 정확히 960x640 이라면 `borderless` 로 두었을 때 화면에 딱 맞습니다.
타이틀바를 켜면 그 높이(약 31px)와 테두리만큼 아래가 잘리므로, 그때는 전체화면
버튼을 쓰십시오.

주 모니터와 보조 모니터의 배율이 다를 때 창이 흐리게 늘어나지 않도록,
`SetProcessDpiAwareness(2)`(모니터별 DPI 인식)를 켠 뒤 tk 배율을 96DPI 로 고정합니다.

## 창 조작

| 동작 | 방법 |
| --- | --- |
| 창 옮기기 | 창의 아무 곳이나 잡고 끕니다. |
| 환경설정 | 배너 오른쪽 위의 톱니바퀴를 누릅니다. |
| 전체화면 | 그 옆의 버튼을 누릅니다. 다시 누르면 원래 크기로 돌아옵니다. |
| 닫기 | 오른쪽 끝의 ✕ 를 누릅니다. 감시 스레드까지 함께 정리됩니다. |
| 키보드 | 창을 한 번 누른 뒤 F11 은 전체화면, Esc 는 전체화면 해제 또는 종료입니다. |

전체화면은 **창이 올라가 있는 모니터**를 채웁니다. tkinter 의 `-fullscreen` 속성은
주 모니터를 채워 버리기 때문에 쓰지 않고, 모니터 좌표를 직접 구해서 맞춥니다.
타이틀바가 없는 창은 초점을 자동으로 받지 못하므로, 키보드 단축키는 창을 한 번 누른
뒤에 닿습니다.

### 중복 실행

한 번에 하나만 뜹니다. 이미 실행 중인 상태에서 다시 실행하면 새 창을 띄우지 않고
원래 창을 앞으로 끌어온 뒤 조용히 물러납니다. 창이 둘 뜨면 같은 폴더를 두 번
감시하면서 로그와 알림음이 겹치기 때문입니다.

이름 붙인 뮤텍스를 하나 잡아 두는 방식이며, 뮤텍스는 프로세스가 끝날 때 운영체제가
놓아 주므로 앱이 비정상적으로 죽어도 다음 실행이 막히지 않습니다. 원래 창을 찾지
못한 경우에만 짧은 알림 상자를 띄웁니다. `--noconsole` 로 빌드하는 탓에, 알리지
않으면 실행이 그냥 무시된 것처럼 보이기 때문입니다.

## 실행 예시

```
# 설정 파일 그대로 실행
ShadowPlayNotifier.exe

# 보조 디스플레이에 항상 위로 띄우기
ShadowPlayNotifier.exe --monitor 1 --topmost

# 타이틀바가 있는 보통 창으로 띄우기
ShadowPlayNotifier.exe --no-borderless

# 다른 폴더를 0.5초 주기로 감시하기
ShadowPlayNotifier.exe --dir "D:\record" --interval 0.5

# 스크립트로 바로 실행 (파이썬 3.8 이상)
python ShadowPlayNotifier.py --monitor 1
```

명령줄 인자가 `config.json` 보다 우선합니다. `--topmost` 처럼 켜는 인자에는
`--no-topmost`, `--no-borderless`, `--no-beep` 처럼 끄는 짝이 있습니다.

## 버전

버전 번호는 [component/version.py](component/version.py) 한 곳에 있습니다.
바뀐 내용은 [CHANGELOG.md](CHANGELOG.md) 에 적고, 배포할 때 같은 번호로 태그를 답니다.

```
git tag v1.0.0
git push origin v1.0.0
```

## 검증 도구

`test/` 폴더에 있습니다. 자세한 사용법은 [test/README.md](test/README.md) 를 보십시오.

```
python test\test_detection.py
python test\test_placement.py
python test\test_single_instance.py
python test\trace_growth.py
powershell -ExecutionPolicy Bypass -File test\preview.ps1 -Mode rec -Borderless
powershell -ExecutionPolicy Bypass -File test\live_check.ps1
```

앱을 실행한 채로 빌드하거나 검증 도구를 돌리면 안 됩니다. PyInstaller 가 실행 중인
EXE 를 덮어쓰지 못해 조용히 실패하고, 창이 둘 뜨면 검증 결과도 어긋납니다.
